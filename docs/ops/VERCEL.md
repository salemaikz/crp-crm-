# Тестовый стенд на Vercel

Нужен, чтобы «потыкать» CRM в браузере и с телефона без своего сервера. Решение — D-318 (статус «предложено»).

> **Только синтетика. Не для данных клиентов.** Серверы Vercel и Neon — за пределами Казахстана, а персональные
> данные граждан РК хранятся только на серверах в РК (D-008). На стенд не вводятся настоящие имена, телефоны,
> компании и таблицы клиентов. Загрузка файлов импорта на стенде закрыта намеренно. Боевая установка — только на
> сервер клиента (`docs/DEPLOY.md`).

## Как это устроено

- Это не учебный стенд в РК (D-030): там пробы и обучение с людьми, здесь — витрина для владельца вне РК.
- Режим включается, только когда одновременно `VERCEL=1` (ставит сама платформа) и `CRM_STAND=1`, только в общей
  сборке и только в сборке Production через `npm run vercel-build` (она вшивает признак стенда в бандл). В сборке
  клиента (ядро с водяным знаком, `CRM_CUSTOMER_ID`) он не включается: запуск и сборка отказывают. Preview-сборки
  идут обычной сборкой без миграций и сида.
- Сборку запускает `npm run vercel-build` (`vercel.json`, `scripts/vercel/build.sh`): ядро → проверка базы (пустая или
  только синтетика `+7 709 …`) → миграции → синтетический сид (500 выдуманных клиентов, сотрудники, мероприятия,
  сделки) → `next build`. Повторная сборка ничего не дублирует.
- Секреты не задаются по одному: `CRM_PHONE_HMAC_KEY`, `CRM_IIN_HMAC_KEY` и ключ секретов интеграций выводятся из одной
  переменной `CRM_DEMO_SECRET`. Адрес стенда берётся из домена проекта (`VERCEL_PROJECT_PRODUCTION_URL`). Флаги модулей
  стенда включены, Wazzup и телефония выключены.
- Ассеты пресета (логотип темы, D-333): режим стенда всегда ставит `CRM_ASSETS_DIR=stand-assets` и перекрывает заданное
  значение. Сид на сборке копирует ассеты в `<корень>/stand-assets`, трассировка кладёт каталог в бандл функций
  (`next.config.ts`), функция читает его оттуда. Переменную в Vercel не задавайте. Каталог закрыт в `.gitignore` и
  `.dockerignore`.
- Функции работают в регионе `fra1` (Франкфурт), рядом с базой Neon.

## Что задать в Vercel

1. **База.** Storage → Create Database → **Neon** (Serverless Postgres), регион **Frankfurt (eu-central-1)** →
   подключить к проекту `crp-crm` для окружения Production. Интеграция сама положит `DATABASE_URL`,
   `DATABASE_URL_UNPOOLED`, `POSTGRES_URL` и другие. Ничего не правьте в них руками.
2. **Переменные** (Settings → Environment Variables, окружение Production):

   | Переменная | Значение |
   |---|---|
   | `CRM_STAND` | `1` |
   | `CRM_DEMO_SECRET` | случайная строка от 32 символов, например вывод `openssl rand -base64 48`. Храните у себя; не меняйте после первого запуска (иначе стоп-лист перестанет совпадать — проще пересоздать базу) |
   | `CRM_SEED_PASSWORD` | общий пароль всех учёток стенда: от 8 символов, не из частых (`password`, `12345678` и т. п. сид отвергнет), не номер телефона. Без него сборка остановится с ошибкой |

   Необязательно: `APP_ORIGIN` — если у стенда свой домен (по умолчанию `https://<домен проекта>.vercel.app`);
   `FEATURE_<ИМЯ>=0` — выключить модуль; `FEATURE_REPORTS_EXPORT=1` — выгрузка отчётов.
   **Не задавайте** `CRM_CUSTOMER_ID`, `CRM_LICENSE_KEYS_FILE` и `CRM_PROXY_SECRET`: на стенде они не нужны.
3. **Пересобрать.** Deployments → последняя сборка → ⋯ → **Redeploy**. Переменные действуют только на новые сборки,
   поэтому после любой правки переменных — Redeploy. В журнале сборки видны шаги `[vercel-build]` и список учёток.

## Учётки

Вход по номеру телефона, пароль у всех — `CRM_SEED_PASSWORD`. Номера служебные, `+7 709 100 00 NN`, как в
`docs/ops/DEMO.md`: администратор — 01, РОП — 02, дежурный — 03, операторы — 04…08, консультанты — 09 и 10,
директор — 11, глава маркетинга — 12. Сценарий показа — там же.

## Чего на стенде нет

- **Воркера.** Раздача лидов по расписанию, напоминания и сводки, сверка явки после мероприятий, создание мероприятий
  на новые недели, проверки и чистки не выполняются. Данные «сегодня» привязаны ко дню первой сборки с пустой базой;
  со временем записи и перезвоны уезжают в прошлое. Освежить — удалить базу Neon (или создать новую ветку), Redeploy.
- **Импорта файлов.** Загрузка таблицы отвечает «На тестовом стенде импорт недоступен»; модуль импорта по умолчанию
  выключен. Таблицы клиентов на стенд не загружаются.
- **Настоящих номеров.** Номер клиента, «Предложить контакт», гость без записи и приглашение сотрудника принимают
  только `+7 709 …`; иначе — «На тестовом стенде — только номера +7 709».
- **Интеграций.** Wazzup и телефония выключены всегда. Приём лидов `ingest/v1` закрыт при любом `INGEST_PUBLIC`.
  Push не настроен.
- **Лицензии.** Общая сборка работает без файла лицензии.
- Лимиты частоты входа считаются в памяти каждого экземпляра функции — на стенде они мягче, чем на сервере.

Работают: вход, все экраны ролей, итоги звонков, записи, сделки, передачи, задачи, отчёты, полная выгрузка, service
worker и установка на телефон как приложение (PWA, https даёт Vercel).

## Ограничения и ловушки

- **Preview-сборки** (ветки и PR) стенда не дают: миграции и сид идут только при `VERCEL_ENV=production`, а без признака
  стенда такая сборка требует окружение боевой установки и не стартует. Смотрите стенд по основному домену.
- База Neon на бесплатном тарифе засыпает: первый запрос после простоя — несколько секунд.
- Если сборка пишет «база не похожа на стенд» — в базе есть номера вне блока `+7 709` или чужие таблицы. Подключите
  пустую базу.
- Без `CRM_DEMO_SECRET` или без базы сборка или запуск останавливаются с текстом, чего не хватает (Deployments →
  сборка → Build Logs или Runtime Logs).

## Проверка у себя «как на Vercel»

```
createdb crm_vercel_local
VERCEL=1 VERCEL_ENV=production CRM_STAND=1 CRM_DEMO_SECRET=<32+ символа> CRM_SEED_PASSWORD=<пароль> \
VERCEL_PROJECT_PRODUCTION_URL=localhost:3311 APP_ORIGIN=http://localhost:3311 \
DATABASE_URL=postgres://…/crm_vercel_local npm run vercel-build
# те же переменные, кроме CRM_SEED_PASSWORD:
… node_modules/.bin/next start -p 3311
```

`APP_ORIGIN` задаётся явно: на localhost нет https. После проверки базу удалить.
