# Демо-стенд на своём компьютере

Нужен, чтобы «потыкать» CRM до появления сервера. Одна команда поднимает базу, накатывает миграции, заливает
**синтетические** данные (500 выдуманных клиентов, `+7 709 …`) и запускает приложение с воркером. Реальных людей
и компаний в данных нет. Подробности сида — `docs/ops/RUNBOOK.md`, «Учебный стенд и демо-данные».

**Не для боевого сервера и не для реальных клиентов.** Секреты демо случайные, лежат в `.demo/demo.env` (папка
закрыта в `.gitignore`, в репозиторий не попадает).

## Требования

- Docker (Docker Desktop на macOS и Windows), запущенный.
- Node.js 22+ и зависимости: если нет `node_modules`, скрипт сам выполнит `npm ci`.
- Свободные порты: 3000 (приложение) и 55432 (база; если занят, берётся следующий свободный).

## Команды

```
scripts/demo/local.sh          # поднять (повторный запуск безопасен) и напечатать адрес, учётки, пароль
scripts/demo/local.sh stop     # остановить приложение, воркер и базу; данные сохраняются
scripts/demo/local.sh reset    # удалить контейнер crm-demo-pg, том crm-demo-pgdata и папку .demo
```

Первый запуск собирает приложение — несколько минут. Журналы: `.demo/app.log`, `.demo/worker.log`,
`.demo/build.log`. Пересобрать после обновления кода: `DEMO_REBUILD=1 scripts/demo/local.sh`.
Переменные: `DEMO_APP_PORT` (по умолчанию 3000, задавать до первого запуска), `DEMO_PG_PORT`,
`DEMO_DATABASE_URL` (своя база Postgres 16 вместо контейнера).

**Windows.** Запускайте скрипт в WSL2 (Ubuntu) или Git Bash; Docker Desktop с включённой интеграцией WSL.
Репозиторий держите в файловой системе WSL (`~/…`), не в `/mnt/c`: так быстрее и без проблем с правами.
Адрес `http://localhost:3000` открывается из обычного браузера Windows.

Вход идёт по `http://localhost`: для localhost приложение выдаёт обычную cookie без префикса `__Host-`
(он нужен только на https), отдельный прокси не требуется.

## Учётки

Вход по номеру телефона, пароль у всех один — печатается в конце запуска, лежит в `.demo/demo.env`
(`CRM_SEED_PASSWORD`). Номера служебные: `+7 709 100 00 NN`, их формирует сид (`scripts/seed/staff.ts`).

| Роль | Телефон | Имя |
|---|---|---|
| администратор | +7 709 100 00 01 | Админ Стенда |
| РОП | +7 709 100 00 02 | Руслан Руководитель |
| дежурный (вторая учётка РОП) | +7 709 100 00 03 | Дина Дежурная |
| оператор | +7 709 100 00 04 … 08 | Айдана, Берик, Виктория, Габит, Дарина |
| консультант | +7 709 100 00 09, 10 | Камила, Леонид |
| директор | +7 709 100 00 11 | Мурат Директор |
| глава маркетинга | +7 709 100 00 12 | Надежда Маркетинг |

Администратор управляет сотрудниками и настройками, но без роли в пространстве карточек клиентов не видит.

## Сценарий показа

1. **Оператор (телефон).** В Chrome откройте DevTools, режим устройства (Ctrl+Shift+M), выберите iPhone или Pixel.
   Войдите как оператор 04. «Звонки» (`/call`): одна карточка, крупная зелёная кнопка; поставьте итог («Недозвон»,
   «Перезвонить», «Договорились» и т. д.), посмотрите, как карточка сменилась на следующую. Затем «Задачи», «Записи»,
   «Клиенты».
2. **РОП (ноутбук).** Выйдите, войдите как РОП 02. «Сводка» (`/summary`): цифры по команде и операторам; «Раздача»,
   «Сделки», «Передачи», «Консультанты», «Команда», «Отчёты» (`/reports`). Посмотрите, что итог оператора из шага 1
   отразился в сводке.
3. **Дежурный и консультант (по желанию).** Дежурный 03 ведёт ближайшие мероприятия (`/duty`), консультант 09 — свои
   консультации (`/consultations`).
4. **Директор.** Войдите как директор 11: только чтение, сводка и отчёты за период; любая правка отвечает отказом.
5. **Глава маркетинга и администратор** — для полноты картины ролей и настроек.

## Ограничения

- Только синтетика; сид отказывается работать на базе с настоящими номерами.
- Данные «сегодня» (перезвоны, записи на ближайшие дни) привязаны ко дню первого запуска. Для свежих дат:
  `reset` и новый запуск.
- Телефония, Wazzup и push выключены; воркер работает (раздача, мероприятия, напоминания).
- Это production-сборка на localhost: другой компьютер в сети по адресу `http://<ip>:3000` войти не сможет
  (origin и cookie привязаны к `localhost`).
