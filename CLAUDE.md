# Claude Code в этом репозитории

Общие правила — в `AGENTS.md` (подключён выше). Здесь только то, что касается
Claude Code.

## Ты — оркестратор

Главная сессия работает как **оркестратор**: понимает задачу, режет её на
подзадачи, присваивает уровень сложности и раздаёт подагентам. Сама пишет код
только в мелочах, где делегирование дороже правки. Политика и таблица уровней —
`docs/agents/ROUTING.md`. План, потоки и зоны файлов — `docs/PLAN.md`. Порядок
действий — скилл `/orchestrate`.

| Уровень | Модель | Подагенты (`.claude/agents/`) |
|---|---|---|
| T0 | Haiku | `scout`, `Explore` — поиск и чтение; `mechanic` — механические правки |
| T1 | Sonnet | `builder` — реализация по ТЗ; `tester` — проверки и тесты |
| T2→T1 | Opus → Sonnet | `architect` проектирует, `builder` реализует, `reviewer` проверяет |
| T2 | Opus | `architect` — схема БД, доступ и охваты, деньги, ПДн, импорт файлов, лицензия, секреты; `reviewer` — ревью перед пушем |

Главное:
- Поиск по коду и чтение длинных файлов и логов — через `scout`/`Explore`, а не
  самой сессией.
- Независимые подзадачи разных потоков запускаются параллельно, в одном
  сообщении. Правки одних и тех же файлов идут последовательно или в разных
  worktree.
- T0/T1 не справился → эскалация на уровень выше, а не повтор той же моделью.
- Перед каждым пушем — `reviewer` (код, docs, решения и `.claude/**`).
  Деньги, доступы, ПДн, миграции, загрузка файлов, лицензия — только через
  `architect` на этапе дизайна, даже если правка выглядит механической.
- В Workflow-скриптах задавай `model` каждому `agent()` по той же таблице.
- Боевых серверов у агентов нет: ни SSH, ни данных. Только локально и стенд.
- Маршрутизация по frontmatter работает с **Claude Code v2.1.251+**
  (`claude --version`; подробности — ROUTING.md).

## Скиллы проекта

- `/start-task <issue>` — начать работу по issue: проверить поток, ветку,
  контекст.
- `/orchestrate <задача>` — разрезать задачу и раздать по уровням моделей.
- `/handoff` — записать передачу работы в конце сессии.

## Настройки

`.claude/settings.json`:
- подагенты без явной модели идут на Sonnet (`CLAUDE_CODE_SUBAGENT_MODEL`);
- инструментам Read и Edit запрещены файлы с секретами: `.env`, `.env.local`,
  `.env.development`, `.env.test`, `.env.staging`, `.env.production`,
  `.env.*.local`, `*.env` (файлы окружения сервера вроде `app.env`), `*.pem`,
  `*.age`, `*.key`, `id_rsa*`, `id_ecdsa*`, `id_ed25519*`, а также
  `license-private*`, `release-private*`, `stage-private*` — так называются
  закрытые ключи лицензий, релизов и стенда. `*.example` разрешены. Те же
  шаблоны закрыты в `.gitignore`.

Через Bash это не блокируется, поэтому правило из `AGENTS.md` действует
отдельно: секреты не читать и не выводить никаким способом.

Личные настройки — в `.claude/settings.local.json` (не коммитится).
